## 2. The run record

These are the standing answers for this run, so that an unattended agent does not stop at a
prompt. The `ship-ticket`, `run-wave` and `run-waves` skills read them as the user's decisions
for this run.

### 2.1 Granted by Matt

- Merging a ticket into `v1-build` needs no further approval.
- Every commit follows Conventional Commits (constitution §12).
- `v1-build` is pushed to `origin`.

### 2.2 Defaults Matt can veto

| Choice | Default |
| --- | --- |
| Pushing ticket branches and opening PRs into `v1-build` | Allowed. This is decision F3's recommendation. |
| Workflow | `full` for every ticket: `prep`, `build`, `review-suite`, `resolve-review`, `prove`. |
| Proof placement | Per ticket. T20 is the proof of the whole. |
| Publication unit | One PR per ticket into `v1-build`, merged by rebase once its gate passes and its proof is attached. |
| Test-first | Red-green TDD for behavior changes. |
| Checkpoint commits | Yes, one per build step. |
| Commit confirmation | `create-commit` commits without asking, because nobody is there to answer. |
| Proof capture plan | A ticket's **Proof** section is the approved capture plan for `prove`. |
| Grilling in `prep` | Off. |
| GitHub issues | None are created or closed. Commits and PRs refer to tickets as `Refs: T07`. |
| Workers | At most two backend tickets and two iOS tickets at once, unless the Space sets another limit. |

### 2.3 Not allowed

Whatever a ticket or a skill suggests (constitution §13): pushing or merging to `main`;
deploying; uploading to TestFlight; anything in Auth0, Neon, Apple Developer or production;
adding a dependency outside TDD §9; force-pushing `v1-build`.

## 3. How a ticket is built

1. Start from the latest `origin/v1-build`:
   `git fetch origin v1-build && git switch -c v1/t07-keys-mcp origin/v1-build`. A new orb
   starts on `main`, which has none of this.
2. Read the constitution, the ticket, and the TDD sections it cites.
3. Build it with `ship-ticket`, using the answers in §2.
4. Run the ticket's **Proof**. Open every screenshot and watch every recording before
   reporting. Save them under `.amp/in/artifacts/<ticket>/`.
5. Run the gate: `just gate-expensive` for a backend ticket, `just ios-test` for an iOS
   ticket, both when it touches both. Then run `ship-gate`.
6. Rebase on `origin/v1-build`, rerun the gate, open the PR, and merge it by rebase.
7. Report with the proof: the commands and their decisive output, the screenshots and
   recordings, what was not checked, and the merged commit.

A ticket that cannot meet its proof is not merged. Report what works, what does not, and what
is needed.

## 4. Shared files

A ticket changes only the files it owns, with these exceptions.

| File | Rule |
| --- | --- |
| `backend/pyproject.toml`, `backend/uv.lock` | T01 adds every approved dependency. No later ticket changes them. |
| `backend/src/feed_the_goose/dtos/`, `clients/openapi.json`, `clients/fixtures/`, the generated Swift client | T02 and T13. A later change lands alone, first (TDD §4). |
| `backend/alembic/versions/`, `backend/src/feed_the_goose/models/` | T04. A later change lands alone, first. |
| `backend/src/feed_the_goose/routers/<name>.py` | T02 creates each as a stub. It then belongs to the one ticket that implements it. |
| `backend/src/feed_the_goose/repositories/<name>.py` | T04 creates the files named in its ticket. Each then belongs to the ticket listed as owning it. |
| `backend/src/feed_the_goose/wiring.py`, `app.py`, `dev/routes.py` | Any ticket may add its own registration lines and nothing else. |
| `backend/tests/conftest.py`, `backend/tests/support/` | T04. Other tickets add a `conftest.py` in their own test folder. |
| `clients/ios/project.yml` | T11. Sources are found by folder, so adding files needs no edit. A ticket that must edit it changes only its own target's lines. |
| `clients/ios/App/RootView.swift`, `App/LiveEnvironment.swift` | T11 creates them, T13 passes the environment through, T14 owns them after that. |
| `justfile`, `backend/justfile`, `clients/ios/justfile` | T01 and T11. A ticket may add a recipe for its own work. |
| `README.md` | T20. |

When two tickets collide in a shared file, the second to merge rebases and keeps both sides'
lines.
